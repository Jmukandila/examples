# Laravel example

A Laravel 13 guestbook on
[`jkaninda/nginx-php-fpm`](https://github.com/jkaninda/nginx-php-fpm), with Postgres for data,
Redis for cache, sessions and the queue. A message is saved as *pending* and published by a
queued job, so a message that stays pending means the queue worker is down.

## One container, three processes

When the image finds an `artisan` file, it starts three processes under supervisor next to nginx
and PHP-FPM:

- `queue:work`, scaled with `LARAVEL_PROCS_NUMBER` (default 1)
- the scheduler, which runs `schedule:run` every minute

So a single Miabi application serves the web, the queue and the scheduler, and no separate
worker app is needed.

## Deploying

[`gitops/laravel`](../gitops/laravel) holds everything this app needs:

| File | Declares |
|---|---|
| `databases.yaml` | A managed Postgres and a managed Redis |
| `secrets.yaml` | `APP_KEY`, generated by Miabi on the first sync and never rotated by later ones |
| `app.yaml` | The app, with the database URLs and the key interpolated into its environment |
| `jobs.yaml` | A Job running `php artisan migrate --force` on every release, and a nightly CronJob running `messages:prune` |

```bash
cd ../gitops/laravel
miabi apply -f databases.yaml -f secrets.yaml -f app.yaml -f jobs.yaml --dry-run
miabi apply -f databases.yaml -f secrets.yaml -f app.yaml -f jobs.yaml
```

Both Jobs set `entrypoint: ["php"]`. The image's entrypoint starts nginx and supervisor and
ignores its arguments, so a job without the override would serve HTTP and never exit.

`APP_KEY` is a 32-character secret. Laravel accepts a raw 32-byte key for AES-256-CBC, so it
needs no `base64:` prefix.

## Behind the Miabi gateway

TLS ends at the gateway, and [`bootstrap/app.php`](bootstrap/app.php) trusts its
`X-Forwarded-*` headers, so generated URLs and Vite assets use `https`.

## The image

The [Dockerfile](Dockerfile) installs Composer dependencies on the same `nginx-php-fpm` image it
ships on, so PHP extensions match, and builds the Vite assets in a Node stage. It caches routes,
views and events. It does not cache config, because that would bake in the build's
environment instead of the one Miabi sets.

## Run it

```bash
composer install && npm install && npm run build
cp .env.example .env && php artisan key:generate
php artisan test
```

## Build from source

Copy this folder into its own repository and create a Git app from it. Miabi offers to adopt
[`.miabi/pipeline.yaml`](.miabi/pipeline.yaml): the tests run in the same `nginx-php-fpm` image,
then the build, a Trivy scan that reports without blocking, and the deploy. Keep the Job from
[`gitops/laravel/jobs.yaml`](../gitops/laravel/jobs.yaml), so migrations run when the release
goes live.
